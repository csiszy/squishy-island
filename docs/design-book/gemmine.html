Gem store · real money

Gem Mine

A sparkly little mine dug into the rocks at the edge of town, glowing with crystals and with a cart full of Gems on its rails. It is the only place in the game where real money is spent: grown-ups buy Squish Gems here, and the Gems are then spent on squishies in the Factory’s Gem Shop.

  • Address: 1 Crystal Rocks
  • Unlocks: built from day one
  • Levels: just one, it never needs upgrading
  • Pays with: real money, through Google Play
  • Also opens from: the 💎 button on the map’s left strip

What happens when you tap a pack

  1. Grown-up gate (every time, not only the first time).
  2. Checks the monthly spending limit and the Purchases on/off setting (both in Settings).
  3. The very first time: a one-line notice that Gems arrive straight away, so the EU 14-day cancellation right ends once they are delivered (wording for the lawyer to confirm).
  4. Google Play’s own payment sheet slides up. The game never sees card details.
  5. The game’s server checks the purchase with Google, adds the Gems, and the counter runs up with a sparkle.

Pending payments (for example cash payments in some countries) show “Waiting for payment…” and the Gems arrive when Google confirms. Cancelling just closes the sheet.

Store rules

  • Real money is always shown next to the Gems, as Google’s price in the player’s own currency.
  • Same price per Gem in every pack. No “best value” labels, no bonus Gems on bigger packs, no countdowns and no “special offer!” pop-ups, so nothing pushes kids toward bigger purchases.
  • Packs of 100 Gems, so players can always buy exactly what a squishy costs (300 or 500).
  • No ads in the Gem Mine, ever.
  • The store is never shown automatically (not after a lost game, not on start-up). Kids only get here by tapping the mine or the 💎 button.
  • Gems can’t be turned back into money, and they only buy things that are not random.

In this design bookPurchases here are pretend: nothing is charged. The Gems you “buy” are saved in this browser and can be spent in the Factory’s Gem Shop demo.

For the builder

Connecting it to Google Play Billing

Set-up in the Play Console

  • One one-time product per pack, all consumable: gems_100, gems_300, gems_500, gems_1000.
  • Prices are set per country in the Play Console. The game never hard-codes a price: it shows the formattedPrice Google returns.
  • How many Gems each product gives lives in a small catalog on the server (below), so it can change without an app update.
  • Use Play Billing Library 8 or newer (required for new apps and updates since 31 August 2026). In Godot it comes through an Android plugin (the public one if it ships Billing Library 8, otherwise our own thin Kotlin plugin), behind the Billing interface below. Nakama checks the purchase on the server.
  • Turn on Real-time developer notifications so the server hears about refunds.

Server rules

  • Gems are only added by the server, after it checks the purchase token with the Google Play Developer API (product, state, not used before, and the player ID sent with the purchase).
  • Granting is idempotent: the same order ID can never add Gems twice.
  • After granting, the app consumes the purchase. Purchases not acknowledged or consumed within 3 days are refunded by Google automatically.
  • On every start the app asks Google for unfinished purchases and completes them (in case the app closed mid-purchase).
  • Refunds and chargebacks (Voided Purchases API) take the Gems back; if they were already spent, the balance can go below zero until refilled.
  1. App start: connect to Google Play Billing → query product details for the catalog IDs → keep the prices. Finish any unfinished purchases.
  2. Store opens: show packs with Google’s prices. If Purchases are off or Billing isn’t available, show a friendly message instead of packs.
  3. Tap a pack: grown-up gate → spending-limit check (server) → launchBillingFlow with the hashed player ID as obfuscatedAccountId.
  4. Result: PURCHASED → send the token to the server · PENDING → “Waiting for payment…” · USER_CANCELED → close quietly · ERROR → “Something went wrong, nothing was charged.”
  5. Server: verify with Google → add Gems → reply with the new balance → app consumes the purchase and plays the Gem animation.

The store talks to one small interface

// The Gem store only uses this. The design book plugs in
// MockBilling; the real game plugs in Google Play Billing.
interface Billing {
  connect(): Promise<boolean>
  products(ids): Promise<[{ id, price, priceMicros, currency }]>
  buy(id, playerId): Promise<{ state: 'purchased' | 'pending'
                      | 'cancelled' | 'error', token? }>
  finish(token): Promise<void>   // consume after the server granted
  unfinished(): Promise<[{ id, token }]>
}
